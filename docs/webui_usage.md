# WebUI 使用说明

## Cookie 自动检测和 Webhook 通知功能

### 访问界面

1. 启动 WebUI 服务：
```bash
uv run uvicorn api.main:app --port 8080 --reload
```

2. 打开浏览器访问：`http://localhost:8080`

3. 点击顶部导航栏的 **"Cookie 包"** 标签页

### 功能区域

在 Cookie 包标签页中，你会看到三个主要配置区域：

#### 1. Cookie 自动检测配置

**位置**：在代理池下方

**功能**：
- 设置定时检测所有 Cookie 是否有效
- 支持 Cron 表达式配置检测频率
- 可以手动触发立即检测

**使用步骤**：

1. **设置 Cron 表达式**：
   - 在 "Cron 表达式" 输入框中输入，例如 `0 * * * *`（每小时检测一次）
   - 或点击快捷按钮：
     - "每小时" → `0 * * * *`
     - "每2小时" → `0 */2 * * *`
     - "每6小时" → `0 */6 * * *`

2. **启用定时检测**：
   - 勾选 "启用定时检测" 开关

3. **保存配置**：
   - 点击 "💾 保存配置" 按钮

4. **手动测试**：
   - 点击 "▶️ 立即检测" 按钮可以立即触发一次检测
   - 检测完成后会自动刷新 Cookie 列表，显示最新状态

5. **查看状态**：
   - 底部显示 "最后检测时间"

#### 2. Webhook 通知配置

**位置**：在 Cookie 自动检测配置下方

**功能**：
- 配置 Webhook 接收地址
- 自定义通知消息格式
- 支持钉钉、企业微信、飞书等机器人
- 可以添加自定义请求头（如认证 Token）

**使用步骤**：

1. **配置 Webhook URL**：
   - 在 "Webhook URL" 输入框中输入你的 Webhook 地址
   - 例如钉钉机器人：`https://oapi.dingtalk.com/robot/send?access_token=YOUR_TOKEN`

2. **选择消息模板**：
   - 点击快捷按钮选择预设模板：
     - "钉钉模板" - 适用于钉钉机器人
     - "企业微信" - 适用于企业微信机器人
     - "飞书" - 适用于飞书机器人
     - "默认" - 通用 JSON 格式
   - 或手动编辑 JSON 格式的消息模板

3. **自定义请求头**（可选）：
   - 如果需要认证，在 "自定义请求头" 中输入 JSON 格式的请求头
   - 例如：`{"Authorization":"Bearer your-token"}`

4. **设置超时时间**：
   - 默认 10 秒，可根据需要调整（1-60 秒）

5. **启用 Webhook**：
   - 勾选 "启用 Webhook 通知" 开关

6. **保存配置**：
   - 点击 "💾 保存配置" 按钮

7. **测试通知**：
   - 点击 "🧪 测试通知" 按钮发送测试消息
   - 检查接收端是否收到通知

8. **刷新配置**：
   - 点击 "🔄 刷新配置" 按钮重新加载配置

### 消息模板变量

在消息模板中可以使用以下变量，系统会自动替换为实际值：

- `{cookie_name}` - Cookie Bundle 名称
- `{status}` - Cookie 状态（ok/expired/error）
- `{reason}` - 失败原因
- `{timestamp}` - 检测时间

### 完整使用流程示例

#### 示例 1：配置钉钉机器人通知

1. 在钉钉群中添加自定义机器人，获取 Webhook 地址
2. 在 WebUI 的 "Webhook URL" 中粘贴地址
3. 点击 "钉钉模板" 按钮，自动填充钉钉格式的消息模板
4. 勾选 "启用 Webhook 通知"
5. 点击 "💾 保存配置"
6. 点击 "🧪 测试通知" 验证配置
7. 在 "Cookie 自动检测配置" 中设置 Cron 表达式为 `0 * * * *`（每小时检测）
8. 勾选 "启用定时检测"
9. 点击 "💾 保存配置"
10. 完成！系统会每小时自动检测 Cookie，失效时发送钉钉通知

#### 示例 2：立即检测所有 Cookie

1. 点击 "▶️ 立即检测" 按钮
2. 确认对话框中点击 "确定"
3. 等待 2 秒后自动刷新 Cookie 列表
4. 查看每个 Cookie 的状态标签：
   - 绿色 "正常" - Cookie 有效
   - 红色 "已过期" - Cookie 失效
   - 黄色 "错误" - 检测出错
5. 如果配置了 Webhook，失效的 Cookie 会自动发送通知

### 注意事项

1. **首次使用**：
   - 页面加载时会自动加载配置
   - 如果没有配置，会显示默认值

2. **配置持久化**：
   - 所有配置保存在 Redis 中
   - 重启服务后配置仍然有效

3. **定时任务**：
   - 定时任务在服务启动时自动加载
   - 修改配置后会立即生效，无需重启服务

4. **Webhook 测试**：
   - 建议先测试 Webhook 配置，确保能正常接收通知
   - 测试消息使用固定的测试数据

5. **JSON 格式**：
   - 消息模板和自定义请求头必须是有效的 JSON 格式
   - 保存时会自动验证格式

6. **安全建议**：
   - Webhook URL 中可能包含敏感 Token，注意保密
   - 建议使用 HTTPS 地址
   - 可以在自定义请求头中添加额外的认证信息

### 常见问题

**Q: 为什么点击保存后没有反应？**
A: 检查浏览器控制台是否有错误信息，确保 JSON 格式正确。

**Q: 测试通知失败怎么办？**
A:
1. 检查 Webhook URL 是否正确
2. 确保 Webhook 服务可访问
3. 查看浏览器控制台的错误信息
4. 检查服务器日志 `logs/web.log`

**Q: 定时任务没有执行？**
A:
1. 确认已勾选 "启用定时检测"
2. 检查 Cron 表达式是否正确
3. 查看服务器日志确认任务是否触发

**Q: 如何查看检测历史？**
A:
1. 每个 Cookie Bundle 会显示 "校验时间"
2. Cookie 自动检测配置区域显示 "最后检测时间"
3. 服务器日志中有详细的检测记录

**Q: 可以配置多个 Webhook 地址吗？**
A: 目前只支持一个 Webhook 地址。如需通知多个地址，建议搭建中转服务。
